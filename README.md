# Skills

My personal collection of agent skills for real engineering. They're small, easy to adapt, composable, and work with any model; each one is a plain folder with a `SKILL.md`, following the open [Agent Skills](https://github.com/agentskills/agentskills) format, so any agent that speaks it can load them.

> This repository is a fork of Matt Pocock's [`skills`](https://github.com/mattpocock/skills). It keeps the structure of the original but maintains its own skills and never merges upstream; the upstream skills still in use are [curated](./third-party/README.md) and installed from it directly.

## Install

Clone the repo and run the sync, from a plain terminal rather than inside an agent session. It links these skills into your agents and installs the curated third-party ones; rerun it to update (it fast-forwards the checkout on `main` first), and `--check` to see what a sync would change, including curated skills that changed upstream.

```bash
git clone https://github.com/simonsteiner/skills && cd skills
./scripts/sync-skills.py
```

Needs git, Python 3.10+ and Node (`npx`). Restart your agents afterwards. To take only this repo's skills, without a clone, use the [skills.sh](https://skills.sh) installer instead: `npx skills@latest add simonsteiner/skills`.

### skills.sh commands

For reference: the [skills.sh](https://skills.sh) CLI that the sync drives. `-g` works on the global store (`~/.agents/skills`) that the sync installs into.

```bash
npx skills@latest add simonsteiner/skills --list                     # list this repo's skills without installing
npx skills@latest add simonsteiner/skills -g --skill pr-body         # install one skill, without a clone
npx skills@latest use mattpocock/skills@tdd                          # try a skill without installing it
npx skills@latest find tdd                                           # search skills.sh
npx skills@latest list -g                                            # what's installed, its source and agents
npx skills@latest remove -g <name>                                   # uninstall, e.g. an archived curated skill
npx skills@latest update -g                                          # update every global skill to latest
```

For the curated skills, prefer `./scripts/sync-skills.py` over `update`: it installs exactly what `third-party/skills.json` lists, into the agents each source names, and links the agents skills.sh leaves out.

## Skill catalog

Skills live in buckets under [`skills/`](./skills/) and split on one axis: who can invoke them. **User-invoked** skills run only when you type them; **model-invoked** skills can also be reached automatically when the task fits ([docs/invocation.md](./docs/invocation.md)). ### Engineering

#### User-invoked

- **[arch-review](./skills/engineering/arch-review/SKILL.md)**: Scans the codebase for deepening, coupling, and maintainability candidates, saves a ranked Markdown report with diagrams and a status table to docs/arch-review/, then implements the batch you confirm as one stacked PR per candidate, decisions recorded, loose ends audited.
- **[docs-refactor](./skills/engineering/docs-refactor/SKILL.md)**: Refactors a repo's docs so each kind of knowledge has exactly one home (README, setup, deployment, .env.example, glossary, ADRs), fixes every claim the code contradicts, and rewrites the agent instructions into a short, high-signal AGENTS.md. Stages the result on a new branch with a report and a PR body.
- **[review-doc](./skills/engineering/review-doc/SKILL.md)**: Reviews a design doc, plan, RFC or spec with fresh sub-agents that never saw the conversation behind it (a paraphrase test, a simplicity-and-reuse check against the code, and an implementation-readiness check), then settles the findings with you, edits the doc, and repeats on what changed until a round comes back clean.
- **[test-review](./skills/engineering/test-review/SKILL.md)**: Reviews a project's test setup for blind spots, wasted effort, and how the tests run; saves a ranked Markdown report with a status table to docs/test-review/, then fixes the batch you confirm (tdd for blind spots, prune-tests for waste), one stacked PR per candidate, loose ends audited.

#### Model-invoked

- **[address-review-findings](./skills/engineering/address-review-findings/SKILL.md)**: Works through the review feedback on GitHub pull requests (one PR, several, or a stack), pulling the unresolved threads, fixing what's real, then replying and resolving.
- **[attach-media](./skills/engineering/attach-media/SKILL.md)**: Uploads local screenshots, images, GIFs, or screen recordings to GitHub and embeds them in a pull request, issue, or comment: the same attachment drag-and-drop makes in the web UI, no external hosting.
- **[conventional-commit](./skills/engineering/conventional-commit/SKILL.md)**: Makes the agent's git commits: writes Conventional Commits v1.0.0 messages and splits the work into atomic commits when it spans concerns.
- **[download-media](./skills/engineering/download-media/SKILL.md)**: Downloads the screenshots, recordings, and files attached to GitHub issues, pull requests, and comments so they can be looked at, including on private repos, where the attachment URLs 404 without auth.
- **[frontend-craft](./skills/engineering/frontend-craft/SKILL.md)**: Designs and builds frontend UI with a deliberate point of view instead of templated defaults: picks the surface's mode, plans a compact token system, reviews the plan against the brief, builds to a quality floor, and checks the render in bounded passes. Also shapes a design direction before any code, critiques or audits existing UI, and handles bolder, quieter, simpler, or polish requests.
- **[pr-body](./skills/engineering/pr-body/SKILL.md)**: Writes a pull request's title and body, shaped by the kind of change: a fix shows before → after, a feature shows it working, a refactor shows nothing changed, a chore stays a few lines.
- **[review-prs](./skills/engineering/review-prs/SKILL.md)**: Code-reviews pull requests on GitHub or Azure DevOps, then comments the findings inline, fixes them and resolves the threads. Covers open PRs that no human has reviewed yet or that changed a lot since their last review, a PR or stack the user names, and a local diff since a commit, branch or tag.
- **[setup-lefthook](./skills/engineering/setup-lefthook/SKILL.md)**: Sets up lefthook git hooks in a project: installs lefthook the way the stack expects, writes a lefthook.yml whose pre-commit jobs fix and check only what's staged, adds a per-file token budget that blocks oversized agent-written files with instructions for splitting them, and blocks em and en dashes in staged files.
- **[sync-and-branch](./skills/engineering/sync-and-branch/SKILL.md)**: Puts work on a fresh branch cut from the up-to-date default branch (or a base the user names), carrying uncommitted changes along when they're the branch's work, or syncs a fork's default branch with its upstream.

## Third-party skills

Skills by other people that I use but don't own are **curated, not forked**: [`third-party/skills.json`](./third-party/skills.json) records which upstream skills are worth having and why, and `scripts/sync-third-party.py` installs them straight from their own repos. The annotated list and the sync commands are in [`third-party/README.md`](./third-party/README.md).
